# State machines in this app

The registry of every place the app keeps a small set of modes and moves
between them: tool flows, drags, async jobs, save and open lifecycles, render
loops. Written 2026-11-09 from a whole-app audit; the build that followed is
specified in `docs/state-machines-pass.md`.

Read this before changing how any tool, drag, loader or save path starts,
ends or is cancelled. Most of the bugs the audit found were one of two
shapes: an exit path that forgot a sibling variable, or two copies of "how
this ends" that had drifted apart.

## How machines are treated

| Treatment    | Meaning                                                                                                                                                                         | What to do when you change it                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Explicit** | The transition table is data, declared with `defineMachine` (`src/shared/machine.js`).                                                                                          | Change the table, then update the table printed below. `src/shared/machineRegistry.test.js` fails until both agree. |
| **Named**    | The states stay in their file, but the rule every copy used to re-derive has ONE definition (a constant, predicate or decision table in a small pure module with its own test). | Change the definition, never a copy. If you need the rule somewhere new, import it.                                 |
| **Left**     | Implicit, and fine that way: small, clear, or well tested.                                                                                                                      | Read the notes in its row first. If you are about to add a third flag to it, promote it instead.                    |

Rules that hold everywhere:

1. **An event a state has no use for is ignored, not an error.** A reply after
   a cancel, a second click on a busy button, an Escape with nothing open.
   `machine.next` returns the same state; `machine.can` asks beforehand.
2. **Every way out of a mode clears everything the mode owns.** Tool switch,
   selection change, Escape, pointer-cancel, window blur, unmount, floor or
   view change. When you add a variable to a mode, add it to the mode's single
   reset in the same change.
3. **Async results carry their identity.** A run id, request id, revision or
   generation, checked when the result lands. A result for a run that is no
   longer the live one is dropped.
4. **Escape reverts a drag.** It puts the geometry back, adds no history
   entry and keeps the selection (owner's decision, 2026-11-08; applied to
   Sketch Studio 2D and the roof tool on 2026-11-09).
5. **A double-click is press, press, double-click.** A handler's
   `onDoubleClick` runs after the second press has already been handled. Test
   with the real sequence.

### `project-open` — opening a floorplan project

`src/features/floorplan/hooks/projectOpenMachine.js`, owned by
`useFloorplan.js` (`openRunRef`, `beginOpenRun` / `advanceOpenRun` /
`cancelOpenRun`). A draft or a file on its way in. Each attempt has a run id;
closing the Open Project dialog cancels the live run, and a run that is
cancelled or no longer the live one neither loads, adopts a file handle,
shows progress nor reports an error. `picking` exists because a file can fail
before its reader reports any progress. The `projectOpening` object the UI
reads is drawn from these stages and keeps its own shape.
Tests: `projectOpenMachine.test.js`, `useFloorplanProjectOpen.dom.test.jsx`.

### `cad-brake` — the press brake station

`src/features/sketchstudio/cad/toolSession.js` (`BRAKE`), owned by
`CadWorkspace.jsx` (`brakeSession.stage`; `null` is `idle`;
docs/sketch-studio-fab-shop.md §9 SM-2). The route's Bend (`goStation`, see
"Shop floor route" below) starts it on the part the shop subject names, the
search-only Press brake command on the selected sheet-metal part (refused,
with a one-click remedy, while the part has a finish or prints). Setup is the operator's picks (gauge edge or
two points, L, angle, Flip sheet, tooling), kept in the session and never
saved; `brakeStation.js` derives the pending hit, its refusals and its
collision from them on every render. The pedal (Bend, Enter or Space) is
refused while the hit has a refusal or a collision; otherwise `STROKE` hands
the viewport a stroke `{ token, ... }`, the shop layer animates it in its own
requestAnimationFrame loop and reports the token at the end, and `DONE`
commits the bend (one model commit) and returns to setup for the next hit. A
re-run of a step is a stroke with `commit: false`. A round bend
(docs/sketch-studio-round-bend.md) is N hits inside one `STROKE`: the shop
layer cycles the ram N times in the same loop and reports the token once, and
`DONE` commits the one bend record. A stroke whose model moved
under it (an Undo mid-stroke) commits nothing. `END` is every write of
`null`: Leave press brake, Esc with nothing picked (Esc first clears a pick
or a scrub), the part going away, or a new selection (`resetSelectionTools`).
Keys never cut a stroke short. No state was added for the side view (SM-2b):
it is a view of the shop layer's pose, not a stage.
SF-3 (docs/sketch-studio-shop-floor.md §6.1–6.2) adds no stage. A pending hit
is a list of bends (`pendingIds`: `pending-hit`, `pending-hit:2`, …): the
punch line through `sheetMetal.js` `strokeBends`, one bend per piece pair,
less the segments in the session's `skip` (indexes into `lineSegments`; any
new line — edge, L, points or mode — resets it, a segment click on the flat
blank toggles it). An etched line clicked on the flat blank sets `mode:
'points'` on it, and its `bend` (angle, direction) the angle and Flip sheet.
`STROKE` animates every member; `DONE` commits them all in one commit, with
one fresh `stroke` id when there are several. The sequence list, its scrub,
Re-run, Earlier, Later and Remove act on whole strokes (`bendStrokes`, keyed by
a stroke's first bend id; since TB-1 on steps, `hitSequence`, see below). A stroke whose tabs are not in line in the part's
present state is a refusal (`not-in-line`), not a collision: it is never posed.
SF-4 adds no stage: the shop-order refusal (`brakeBlocked`, no session) lists
the part's hits made and its folded size, read only; a collision's "bend this
one before bend N" is only offered when that order keeps every stroke of
several tabs in line.
BT-2 (docs/sketch-studio-brake-flip-tooling.md §5) adds no stage. Turn sheet
around and Flip sheet are setup picks (`turned`, which any new line resets,
and `flip`); the sheet turning over on the die when the side up changes is a
view of the shop layer (its own animation loop, `station.turn`), not a stage.
An offset bend (Bend shape Offset) is two hits inside one `STROKE`, as a round
bend's are: the stroke carries `run.hits` (each hit's pose) and a
`pairTimeline` (hit one, the sheet turned over for `TURN_MS`, hit two); the
shop layer plays both in the same loop and reports the token once, and `DONE`
commits the two ordinary bend records in the order made, in one model commit
and with no shared `stroke` id (two hits in the sequence). The pedal is
refused while either hit, in the order chosen, has a refusal or a collision.
A re-run of a step that lies the other way up from the pose shown turns the
sheet over first, inside the same `STROKE` (not on a replay's clock).
TL-1 (docs/sketch-studio-brake-tool-length.md) adds no stage. The punch and
die length are setup picks (`punchTrim`, `dieTrim`: mm off each end of every
tooling run, null fitted), reset to null by any new line exactly where `skip`
is (and in the Turn the sheet around trial, which takes a new edge) — until
TL-2 (§9): since then a new line keeps them, and the session gains
`punchHold` / `dieHold` (absent until a length is set: the length in mm a
tool is held at while one run stands under the line), kept in step by
`brakePatch` (`holdTools`: a trim patch sets the hold, a new line derives the
trim from it, a `skip` patch re-reads it) and carried by `brakeCarry`. Unlike
`reverse` they ride in the pending bend's fields, so `DONE` commits them on
the records and a stored step is rechecked, re-run and replayed with them.
The length fix and the taller-punch trials of a ram hit run only under
`advise` (after the settle, or on the pedal), like the punch fix.
HO-1 (docs/sketch-studio-brake-hands-on.md §5) adds no stage. Flip over and
Turn around in the view toolbar, F / T and the grip's handles on the sheet
make the very patches the panel's Flip sheet and Turn sheet around make
(`brakeHands.js` `brakeActPatch`), applied through the one rule
`brakeStation.js` `brakePatch` (a new line resets `skip` and `turned`; the
trims until TL-2), which `changeBrake`, the collision card's turn trial and the grip's
outcomes all call. A handle drag is view only until it commits that one
ordinary session patch: the shop layer moves the drawn sheet along the turn
the act will make, and on the patch's new view carries that turn on from
where the hand let go (`handover`); short of 90°, Esc, a right press or a
lost pointer ease it back with no patch. The outcomes (`advise: false`) are
worked out once the session is still in `setup` with no scrub, kept with the
session / model / params they were made for, or, where the pair would pass
50 ms, on the first approach of each handle. The sheet now also turns (a
view of the shop layer, as the turn-over) when the edge facing the backgauge
changes, not only the side up (`turnChanged`).
HO-2 (docs/sketch-studio-brake-hands-on.md §6) adds no stage either. An edge
clicked on the sheet is the flat-blank card's own `onPickEdge`
(`pickBrakeEdge`, one function for both); the backgauge fingers dragged send
each new L, at most once a frame, through the card's own `onDistance`
(`brakeDistance`), so a finger drag is the card's punch-line drag seen from
the machine: every L is an ordinary setup patch (a new line: `skip`,
`turned` reset, the lengths kept since TL-2, as on the card). Esc, a right press or a lost
pointer put the line back with one patch (`brakeHands.js` `fingerRestore`:
it names `skip`, so it is not a new line and restores exactly). A click on the
fingers or a blade opens the panel on the L field or that blade's picker:
pane state only (`brakePicker`, lifted out of `Blades`; `brakeFocus`, a
one-shot request), cleared when the station starts or is left. Nothing is in
reach in a scrub, a stroke or the replay (the grip prop's `shown` / null).
BQ-1 (docs/sketch-studio-outline-edit-sheet-nest.md §7) adds no stage. The
bend queue's Previous part, Next part and rows, and a job board row, move the
brake through `goStation('bend', { instanceId })`: `END` on the old session,
`START` on the new one. The carry (§7.3): when Bend moves to another part
without the station being left, the new session starts from
`brakeSessionDefaults()` with the old one's `punch`, `die` and `reverse`
(`brakeStation.js` `brakeCarry`); `goStation` reads it from the open session,
or — while the brake shows no session — from the card or gate holding it
(`brakeBlocked.carry`: a painted part's Finished card or the shop-order
refusal; Bend's gate on a part whose blank does not fold, `shopGate.carry`),
so it passes through a part that cannot be bent and on to the next. Every
other way out (Leave press brake, Esc out, another station, a new selection,
the part going away) drops the session and those holders, so the next visit
starts from the defaults (since SP-1 with the remembered punch, below). The
picks never carry.
TB-1 (docs/sketch-studio-tight-bends.md §4) adds no stage. A pending line on
a made bend's line (`brakeStation.js` `madeLine`: the same segments within
0.05 mm) is that bend's next hit: `pending.again`, the stroke runs from the
angle the bend stands at (`run.from`, the shop layer's approach and
`strokeAt` start there), and `DONE` commits the bend-on entries (`again`, no
line; one per tab, a fresh `stroke` when several) in the one commit. Arriving
on such a line is a setup patch like any (`brakePatch(session, patch,
station)`: an angle not above the bend's becomes 90° or 180°, recorded as
`session.arrived` and put back if the line moves on before the angle is
touched; the commit clears it). Bend on on a sequence row is one patch (the
line, `skip`, the sheet the right way round; the trims fitted until TL-2,
which keeps the tools' lengths). The sequence
list, its scrub, Re-run, Earlier, Later and Remove act on steps
(`sheetMetal.js` `hitSequence`, keyed by a step's first record id: a bend-on
step's own id); Remove of a bend's first step takes its bend-on entries too,
and a move that puts a bend-on entry before its bend is refused by the fold
(`foldProblem`) before the sequence check.
TB-2 (docs/sketch-studio-tight-bends.md §5) adds no stage. The tries (this
hit earlier in the order; a made step part-way first) run only under
`advise` (after the settle, or on the pedal), never per drag sample, and a
try the card offers is a setup patch `{ armed }`: `session.armed` is `{ kind:
'before', key }` or `{ kind: 'partway', key, angle }`. While armed the
station checks, poses and (on `STROKE`) animates the hit as the sheet stands
then (`pending.armed`, `pending.others`), including that every later step is
no worse (a refusal `order` otherwise), so the pedal re-checks it as any hit.
`DONE` commits `stroke.placed` (the records at their place, or the step's
angle changed and a bend-on entry appended) in the one commit, clears
`armed` and leaves `session.notice` for a part-way commit. Disarmed by Esc
(the first Esc only disarms, the line stays), Cancel, `brakePatch` of a new
line, a segment toggle, `flip` or `shape`, a sequence edit
(`changeBrakeBends`) and the commit; a stale `armed` (its step gone) is
ignored by the station. A stored step that collides gets `sequenceTries`
(worked out `LIVE_DEBOUNCE_MS` after the checks settle, kept with the checks
they were made for) as row buttons committing through `changeBrakeBends`.
SP-1 (docs/sketch-studio-shop-punches.md §5) adds no stage. A visit that
starts with nothing carried starts from `brakeSessionDefaults()` with the
punch of the last hit committed on this computer and the way round it was
clamped (`brakeMemory.js`: `rememberPunch` in `DONE`'s commit, sharp punches
only; `rememberedPunch` where `START` builds the session; localStorage
`sketchstudio.brake.punch`, an unknown key, a bad value or a storage that
throws falling back to the defaults); a carry, when there is one, wins. The
stroke carries `run.takeOff` (the slant the return takes the part off along,
`brakeCollisions`' `takeOff`, or null; an offset's per hit in `run.hits`; a
re-run's from `takeOffOf`): during `return` the shop layer slides the drawn
part along Y and the side view its sheet. View only: no stage, the committed
pose unchanged. The punch tries of the card (every sharp punch in the rack)
run under `advise` only, as before.
SP-2 (docs/sketch-studio-shop-punches.md §6) adds no stage. A third try (this
hit before a made step, and that step, or up to three later steps, made with
another punch of the rack; tried at one place, and only when the card offers
nothing else for this hit) is armed as `{ kind: 'before', key, punches }`,
`punches` `{ [record id]: punch key }` (session only, no model key).
`armedOf` keeps an entry only for a record of a sharp step after the place
naming a sharp punch of the rack (else the entry is dropped and the try is
plain try 1; a part-way try never carries `punches`) and adds `changes` for
the card's words. While armed the station checks the trial with those
punches (`placedBends` writes them on those records), so the pedal re-checks
it; `DONE` commits `stroke.placed` — the hit at its place and the changed
punches — in the one commit (one Undo), clears `armed` and leaves
`session.notice` "Bend {m} is now made with the {name} punch." (numbered as the
rows read after the commit; the status line's name is "Punch changed"). What
disarms is what disarms try 1. A stored row stopped by its punch or holder may
get a third row button (`sequenceTries`' `punch`), committed through
`changeBrakeBends` as a move. The card's punch tries check a candidate on
`brakeCollisions` first (§6.5); all of it under `advise` only, as before.
TB-3 (docs/sketch-studio-tight-bends.md §7) adds no stage. A new line (edge,
L, points or mode) that lies along a made bend within half the V of the
hit's die, but not on its line already, and crosses no material those bends
do not bend (a made tab's unbent twin on the line: no seat), seats on it inside the same
`brakePatch` (`brakeStation.js` `seatOf`: the line moved onto the bend, off
the session's own gauge edge, or two points along it), before the arrival
rule, which then runs on the seated line. The session records it next to
`arrived`: `session.seated` `{ number, off, from }` (`from` the L asked for,
gauge mode; null for two points), cleared to null by the next new line that
does not seat and by `DONE`'s commit; a session that never seated has no
key. A segment toggle is not a new line and leaves it. Esc on a finger drag
puts it back with the line (`fingerRestore` names `seated`). A finger drag
whose L seats is still one ordinary patch per L: the fingers stand at the
seated L, the chip reads it and the bend. The refusals left (a session that
reaches the station unseated, or a short leg along a made bend) carry
`pending.seat` `{ key, number, off, label }`, a button calling the same Bend
on as the sequence row (`bendOnBrakeStep`), as does a made bend's line
clicked on the flat blank. All synchronous, no `advise`.
PL-1 (docs/sketch-studio-punch-library.md §4) adds no stage. Horn sections
are a tooling pick, `session.horns` (false by default): a new line keeps
them (as it keeps the trims since TL-2), `brakeCarry` carries them with the punch to the next
part (named only when on), and `punchChoice` clears them for a radius punch.
Like the trims they ride in the pending bend's fields (`horns: true` only
when on), so `DONE` commits them on the records and a stored step is
rechecked, re-run, replayed and drawn with them (`brakeFrame` passes the
record's `horns` to the check and the scene). The card's horn try (the hit
with `horns: true`, a button only when it passes every check) runs under
`advise` only, before the length fix. PL-1.1 (§4.8) keeps the shape:
`horns` is false, `true` (the standard, as the checkbox and the card set it)
or a horn's key (25, 30, 55; 20 reads as the standard), read everywhere
through `shopCatalog.js` `hornOf`; the card's try walks the horns shortest
first (with horns on, the longer ones), still under `advise` only.
CG-3 (docs/sketch-studio-corner-gaps.md §5) adds no stage and no session
field, but a collision kind: a hit whose stroke is otherwise clear is checked
once more at its end at the sheet's true thickness (`brakeStation.js`
`thicknessHit`, cornerGaps.js `foldOverlaps`; the stroke itself stays on the
mid-surface) and, where one flange's metal ends inside another's, collides
`{ tool: 'part', thickness: true, phase: 'end' }`. It refuses the pedal like
any collision and shows on a stored step's row (`sequenceChecks`) and an
offset's hit. It is part of the facts (synchronous, not under `advise`) and
never of a search: every remedy trial (`brakeStation({ thickness: false })`,
the "no worse" rule, `sequenceTries`' trials) leaves it out and counts the
part as made without it, and a hit or row refused for it gets no try (no turn,
punch, length, horn, order or part-way bend).
SG-1 (docs/sketch-studio-skin-gauge.md §4) adds no stage. In gauge mode
`session.distance` is what the backgauge reads, off `session.stop` (null:
the gauge edge; a made bend's id: the outside face of its flange, an id the
fold no longer has read as null); `sessionLine` puts the line L plus that
stop's take-up from the edge (`brakeStation.js` `flatDistance`, the take-ups
cached per fold object). `session.stopHold` (null automatic, `'edge'` or a bend
id: the panel's Gauge off) is the operator's own stop; a new edge, the mode or
the points clear it. `brakePatch`, the one rule, on a new line: a patch naming
`stop` is taken as given (the writers of a flat distance name `stop: null`:
the flat-blank card's drag always; Bend on / the seat's `lineOnBends` and
Turn sheet around wherever it could be read otherwise, the edge having bends
in front of it or the session a stop; the "move the line" remedy names the
session's own); else the held stop, else the
automatic rule (`automaticStop`, §4.4: the nearest stop that can make the
line; a finger drag's patch-only `dragStop`, the stop it started on, tried
first); then the seat and the arrival as before, on the line that gives; last
(also for a patch naming `stop` with its `skip`, Bend on) the line is written
canonical (`lineStop`: the nearest made bend strictly between the edge and the
line, `distance` what the fingers read off it; the flat line unchanged). Under
a held stop the line has left, the held stop stays and the station refuses
the hit (`gauge-stop`, with the one click that gauges off what the fingers do
stop on). A patch that is not a new line leaves `stop` alone; Esc on a finger
drag puts it back with L (`fingerRestore` names `stop`). `brakeSessionDefaults`
has `stop: null`, `stopHold: null`; `brakeCarry` carries neither. The reading
(`pressBrake.js` `brakeReading`) is synchronous, as the flat one was.

### `cad-paint` — the paint booth

`src/features/sketchstudio/cad/toolSession.js` (`PAINT`), owned by

### `cad-laser` — the laser station

`src/features/sketchstudio/cad/toolSession.js` (`LASER`), owned by
`CadWorkspace.jsx` (`shopSession` with `station: 'laser'`; `null` is `idle`;
docs/sketch-studio-fab-shop.md §9 SM-4). The laser is a station of the
shop's one session, so every hand-listed "another tool is active" site
that names `shopSession` covers it. The route's Cut starts it on the shop
subject's sheet-metal part, the search-only Laser command on the selected one
(refused without one); Cut on the laser (the Cut panel, shop floor §4.5)
starts it already cutting — `START` then `CUT` in one write, once the commit
that makes the part has reached the workspace (`pendingStation`), and only
when the blank has no refusal; the laser opens while the solid is still
rebuilding (it works from the blank alone); the selection is kept, because the
laser bed (`LaserStation.jsx` `LaserBed`) covers the whole 3D view and takes
its clicks (`shopPick` is `null` for the laser: the viewport has nothing to
pick). At `sheet` the stock sheet (a kernel-inert commit to
`model.fabrication.shop.sheet`), the quantity and the bed's view (session
state) are set, and Etch bend lines / Clear marks commit the feature's
`marks` (a part edit: the kernel rebuilds once and builds the same solid; it
never reads marks). `CUT` is refused while the blank has a refusal; it hands
the bed a run `{ token }`, which animates in its own requestAnimationFrame
loop (the SVG rewritten in place, no React render per frame) and reports the
token at the end: `DONE` (a stale token is ignored). `STOP` is the Stop button
or Esc during a cut; Esc at `sheet` and Leave laser are `END`, as are a new
selection (`resetSelectionTools`) and the part going away or ceasing to be
sheet metal (`liveShopSession` ends it). A cut writes nothing to the model.
Edit outline (OE-1, docs/sketch-studio-outline-edit-sheet-nest.md §3.6; on
the panel and on `LaserError`, off while cutting or while the kernel is not
current) is an `END` too: the shop session goes (`leaveStations`) and the
sketcher opens on the blank's sketch with `returnTo: { panel: 'shop-laser',
instanceId }`; its Finish (or Cancel) opens the laser again on that part —
`START`, so `sheet`, not cutting, `cut: false` — through
`openStationOn('cut', …)` (a blank it cannot take opens the gate), with the
notice "Outline updated: blank {w} × {h} mm."
SN-1 (docs/sketch-studio-outline-edit-sheet-nest.md §4, §4.9) changes the
session's fields, not the table. The session is `{ station: 'laser', stage,
key, instanceId (the lead: Quantity, Edit outline and the etched marks act on
its part), instanceIds (the job when the session names it — a batch, null:
every instance of the lead's part), fresh (Quantity's new copies not yet seen
in the model), sheetIndex (the sheet shown, null: the one holding the lead),
view (null until the user picks Close-up / Whole sheet: Close-up only while
the shown sheet holds this one blank and nothing else), run, cut, runKey }`;
`quantity` is gone. The station (`laserStation.js`) is derived from the model:
`sheetNest` puts every blank of the lead's stock and thickness on the shared
sheet. Quantity is a model commit at `sheet` (`changeLaserQuantity`: new
instances of the lead's part in rows beside it, or the newest copies removed
through `removeInstance`, never the lead nor a painted, printed or grouped
copy — those that stay are said on a warning card, `copiesNote`); its new
copies join a named job (`instanceIds` and `fresh`, so `liveShopSession` does
not drop them before their commit is seen). A This cut row (`leadLaser`)
changes `instanceId` and freezes `sheetIndex` at the sheet shown (the job, the
sheet and `cut` stay); the bed's Sheet switch sets `sheetIndex`; neither is a
transition. `CUT` is also refused on a sheet that holds none of the job ("None
of this part is on this sheet."). Cut on the laser on a batch opens with
`instanceIds` = every new instance (`pendingStation.instanceIds`), cutting at
once unless a part of the job has a refusal. Edit outline's `returnTo` carries
a named job (`{ panel: 'shop-laser', instanceId, instanceIds }`), so Finish or
Cancel reopens the laser on the same job. `liveShopSession` keeps the job's
instances still in the model and ends the session when the lead goes. The
replay's laser scenes (`cad-film`) hand the station the scene's `instanceIds`
and `cutIds` (the instances of the cut scenes already played).
RC-2 (docs/sketch-studio-cut-pick.md §4.3) adds no transition: at `sheet`,
while outlines are ready to cut (`readyOutlines`, worked out only while the
laser is on show), the panel says "{n} outline(s) waiting to be cut." with
Cut another outline (off while cutting): `goStation('cut', { outline: {
kind: 'pick', selected: [], stock, thickness } })` — `END` through
`leaveStations`, then Cut's picker on the laser's stock and thickness. The
route's own Cut, while the laser is open, still does nothing.
Tests: `toolSession.test.js`, `CadWorkspace.laser.dom.test.jsx`, `CadWorkspace.outline.dom.test.jsx`, `CadWorkspace.nest.dom.test.jsx`, `CadWorkspace.cutPick.dom.test.jsx`, `sheetNest.test.js`.

    sheet --END--> idle
    cutting --DONE--> sheet
    cutting --STOP--> sheet
    cutting --END--> idle

### `cad-film` — replay the build

`src/features/sketchstudio/cad/toolSession.js` (`FILM`), owned by
`CadWorkspace.jsx` (`shopSession` with `station: 'film'`; `null` is `idle`;
docs/sketch-studio-shop-floor.md §8, SF-5). The route bar's Replay (or the
press brake's Watch the bends on a finished part, which plays that part's
hits only) starts it on the shop subject's product: the scenes
(`shopFilm.js` `filmScenes`) are fixed at the start, together with `source`,
the model it plays, and `before` — the open station's session (shop or press
brake), the brake's refusal card, the gate, the panel, the unfold view and
the problem / notice lines. Being a station of the shop session it is
covered by every hand-listed "another tool is active" site that names
`shopSession` (the ribbon, the tree, Measure, the hole tool, the gizmo, the
group and placement keys), so it needed no new member anywhere; the route's
`routeBusy` adds it (the station buttons, More, Back / Next and the job board
rows wait) and `activeTool` reads `'film'`. It writes nothing: the viewport is
handed the model with only the finishes and prints that exist at the scene
(`filmModel`: kernel-inert keys, so `sameKernelInput` holds and no build
starts), the mask of the parts not made yet (`filmHidden` →
`shopLayer.setHidden`: bought-in items and fasteners come on in the finished
scene), the press brake's
view-only re-run of the hit (`brakeStation.js` `rerunStroke`, its stroke on
the film's clock), the laser bed's cut (`LaserBed` with `watch` and `clock`;
SN-1: the scene's copies are the job on the shared sheet, `cutIds` the
instances of the cut scenes already played, so earlier blanks lie there cut
and later ones as their programmed path; the bed's `view` starts null, the
bed's own choice) and no selection, isolation, explode or section; New, Open, Undo, Redo and
the undo / redo / Delete keys wait, and the view toolbar and cube are inert.
Should the model change anyway, `liveShopSession` ends it. `PAUSE` / `PLAY`
stop and run the clock (`shopFilm.js` `createFilmClock`, a ref the stations'
frame loops read: no React render per frame); `STEP` (previous, next, a row
of the step list) moves to a scene from its start without changing whether
it plays; each scene entry bumps `take` (the stations' run tokens) and a
layout effect puts the clock at 0 before any frame loop reads it. The
workspace's frame loop draws the progress bars, sets `progress` at the
scene's beats (the colour, a print appears: one render each) and at
the scene's end moves to the next; the last scene's end is `DONE`, which
waits on the finished product (`PLAY` there starts it again). Esc, End
replay (the panel, or the route's button) are `END` and put `before` back as
it was; the viewport puts back the camera it kept as the film started (and
the press brake's saved camera and key with it, so a brake that was open
comes back on its own camera). A new selection (`resetSelectionTools`) also
ends it, without putting `before` back, as it ends any station.
Tests: `toolSession.test.js`, `shopFilm.test.js`, `CadWorkspace.film.dom.test.jsx`, `CadViewport.brake.dom.test.jsx`.

    playing --END--> idle
    paused --PLAY--> playing
    paused --STEP--> paused
    paused --END--> idle
    ended --PLAY--> playing
    ended --STEP--> paused
    ended --END--> idle
